# Product Requirements Document — Farmer Digital Ecosystem — v0.1 (draft)

## 1. Vision
A digital companion for every Indian farmer: identity, documents, farm records and services in one accessible platform, complementing (not replacing or impersonating) official AgriStack infrastructure.
Ambition: complete ecosystem · Audience: all Indian farmers · Platforms: Web + Android · Languages: Marathi, Hindi, English (architecture open to more).

## 2. Problem statement
- Farmer records exist as scattered PDFs/screens (e.g. the AgriStack "Farmer Registration Form") that are hard to carry, share, print or verify.
- Many farmers lack smartphone fluency, English, or email; operators help them in person.
- Extracting data from these PDFs by hand is slow and error-prone.

## 3. Product boundaries (hard rules)
1. A platform-generated ID/card is never presented as an official AgriStack Farmer ID or government credential. Every card carries a visible disclaimer (the reference card already does: *"This card is for personal use only and is not accepted as a government identity document"*).
2. We do not use the AgriStack logo or government branding without authorization.
3. Government verification (L3) comes only from an authorized source, never from AI reading a PDF.
4. Farmers control their data and sharing.
5. Land ownership is not mandatory for registration.
6. AI extracts → backend validates → authorized human approves.

## 4. Users and roles
Farmer · Operator (assisted registration) · Verifier · Admin · Super Admin · Auditor · Viewer. RBAC + record-level authorization (see Security doc).

## 5. Release plan
- **Release 1 (MVP) — Identity foundation:** auth/roles, PDF upload, extraction, human verification, farmer profile, document wallet, card generation, QR verification, operator dashboard, i18n foundation, audit.
- **Release 2:** schemes, weather/crop alerts, crop & farm management, financial diary, advisory.
- **Release 3:** marketplace, FPO network, finance/insurance integrations, advanced AI.

### 5.1 First vertical slice (build first)
Upload PDF → extract fields → review/correct → approve → generate card (PNG + printable PDF) with QR → public verification page.

## 6. Reference analysis (from supplied samples)

### 6.1 Source document: "Farmer Registration Form" PDF
- Generated by jsPDF; 4 landscape A4 pages, each a single rasterized image (about 2668 px wide), **no text layer and no vector content**. Native text extraction yields nothing, so OCR/vision is required for this document type.
- Page structure: **p1** header, photo, farmer details, contact, bank/additional, residential, farmer type · **p2** land ownership table + "Annexure" heading · **p3–p4** Aadhaar consent text (English + Marathi), date, farmer name. Only p1–p2 carry data we need; p3–p4 can be skipped (and need not be sent to any AI).
- Fixed layout, bilingual (English labels; Marathi/Devanagari values and consent text).
- **Layout quirks the extractor must handle:**
  - Land-table cells wrap mid-word ("MAHARAS / HTRA", "YAVATM / AL", "Borgao / n") — rejoin before validating.
  - Numbers carry stray punctuation ("1.200000,"); S/S no. may be "*" (means none).
  - The table may have several rows; the "Annexure" heading suggests overflow rows can continue elsewhere. Needs more sample forms to confirm.
  - Many bank/KYC fields are blank; blank must stay blank (never inferred).
- **Name inconsistency within the same document:** header name and the land-table owner name are spelled differently (e.g. a header "सुनीता रामचंद्र पाटील" against a table owner "सुनिता रामचंद पाटील" in an invented example). Real records mismatch like this, so the verification UI must flag name differences between sections instead of auto-merging.
- Also note: the Farmer ID (11 digits) is distinct from the enrollment number (`27_500_...`); both must be captured and labelled.
- Fields observed:

| Section | Fields |
|---|---|
| Header | Farmer enrollment number (e.g. `27_500_0000_000000_000000`), Farmer ID (11 digits), Farmer photograph |
| Farmer details | Name as per Aadhaar (English), Name in local language, Gender, Caste category, Date of birth, Age, Identifier name (English + local) |
| Contact | Mobile number, Email |
| Bank & additional | Caste cert no., PAN, minority religion, KCC number/amount/bank, bank name, branch code, IFSC, account number, disabilities (often blank) |
| Residential | Address (English + local), Farmer type (e.g. Owner), Occupation |
| Land ownership (table, multiple rows) | State, District, Sub-district, Village, Survey No. (S No.), Sub-survey (S/S no.), Owner name, Identifier name & type, Owner type, Owner share type, Total area (ha), Assigned area (ha) |
| Consent / annexure | Aadhaar-related consent text (English + Marathi), date, farmer name |

- Sensitive: bank/PAN/Aadhaar-linked fields are out of scope for the card and should be excluded or redacted at ingestion (data minimization).

### 6.2 Reference card (photo of an AgriStack-style "शेती परिचय पत्र")
Layout: header bar (title in Marathi) · photo (left) · QR (top right) · name (Marathi + English) · DOB · gender · mobile · Aadhaar number · green footer bar with "फार्मर आयडी" + Farmer ID · second panel: full address (Marathi + English) · land details table (district, taluka, village, gat no., area in hectares) · bottom disclaimer note.

## 7. Functional requirements (Release 1)
- **FR-1 Upload:** staff upload PDF (type/signature/size/page-count validation, random storage name, quarantine, SHA-256 duplicate detection).
- **FR-2 Extraction:** pluggable extractor returning schema-typed fields with confidence and source page/region; template-aware for the known Farmer Registration Form layout; generic fallback for other layouts.
- **FR-3 Verification UI:** side-by-side page image and editable fields, low-confidence highlighting, required human approval, change history.
- **FR-4 Farmer profile:** identity, contact, address, land parcels (many), farmer type; separate entities for person, parcels, cultivation, credentials.
- **FR-5 Trust levels:** L0 Draft · L1 Submitted · L2 Document reviewed · L3 Officially verified (authorized source only) · L4 Reverification required. Level shown on card and verification page.
- **FR-6 Card generation:** bilingual (Marathi/English) card matching the reference layout without government branding; PNG + print-ready PDF; versioned; disclaimer mandatory.
- **FR-7 QR verification:** random high-entropy token (stored hashed), URL-only QR, public page shows minimal authorized data, status valid/invalid/revoked/expired/updated, timestamp, rate-limited.
- **FR-8 Wallet:** store original and derived documents with provenance (never labelled "government verified" unless L3 source).
- **FR-9 Audit:** who/what/when/outcome/correlation ID; no personal data in logs.
- **FR-10 i18n:** Marathi, Hindi, English UI; Indian date/number formats.

## 8. Non-functional requirements
Security per `SECURITY_ARCHITECTURE.md` · accessibility (large touch targets, low-data mode, screen-reader) · extraction latency target < 30 s per document · availability and backup/restore tested · all processing server-side.

## 9. Zero-cost strategy (current constraint: no budget)
| Component | Free option | Caveat |
|---|---|---|
| OCR (default) | Tesseract with `mar`, `hin`, `eng` models, or PaddleOCR — local | Best fit for this fixed-layout form: crop known regions, OCR each, validate with regex. Real data stays local |
| AI extraction | Gemini API free tier | **Synthetic/redacted data only** (may be used for training). Fine for prototyping and OCR benchmarking |
| Database | Local PostgreSQL (Docker) for dev; free-tier managed Postgres later | Free tiers have limits and may sleep |
| Storage | Local filesystem behind a storage interface; S3-compatible later | |
| QR / card / PDF | `qrcode`, `sharp`/`satori`, `pdf-lib`/Puppeteer — open source | Devanagari font embedding (Noto Sans Devanagari, free) |
| Hosting | Local during development; free tiers for demo with synthetic data only | Do not host real farmer data on free tiers |

Recommendation: build with **local OCR first**; keep Gemini behind the adapter for hard cases and synthetic-data experiments.

## 10. Risks
| Risk | Mitigation |
|---|---|
| Card mistaken for official ID | Mandatory disclaimer, distinct branding, platform ID label |
| Real farmer data in dev/test | Synthetic samples; `.gitignore` for supplied files; local-only processing |
| OCR errors on Devanagari | Region-based OCR, validation, mandatory human review, benchmark set |
| Form layout changes | Template versioning + generic fallback |
| Name/value mismatch between form sections (seen in sample) | Cross-field consistency checks; flag for human review |
| Wrapped/hyphen-split words in table cells | Post-OCR cleanup + validation against known state/district lists |
| Legal (DPDP, Aadhaar Act) | Legal review before real data; minimize fields |
